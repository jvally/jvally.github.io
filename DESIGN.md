# DESIGN.md — Vishesh Jally portfolio

Read this before changing styles; update it when a token or component changes.

## Direction

Blue sky. Flat two-tone panels float over a deep-blue gradient with soft clouds drifting behind and in front of them. A dial sits on the seam of the hero panel with a paper plane at its centre (a nod to paper modeling). One warm accent, orange, against all the blue.

The content still reads as a shell session: each section is a command in a dark rail with its output beside it, and a terminal bar at the bottom unlocks sections in order.

## Tokens

RGB triplets in `:root` of `src/input.css`. Change a value there and every utility follows.

| Token | Tailwind name | Value | Role |
| --- | --- | --- | --- |
| `--color-navy` | `navy` | `#081f70` | Dark half of panels, rail, cards, terminal, header |
| `--color-azure` | `azure` | `#114fc4` | Light half of panels |
| `--color-line` | `line` | `#ffffff` | Hairlines and borders, always with alpha (`border-line/15`) |
| `--color-text` | `text` | `#e8f0ff` | Body text |
| `--color-muted` | `muted` | `#bed2f8` | Secondary text, dates, stack lines |
| `--color-heading` | `heading` | `#ffffff` | Headings |
| `--color-accent` | `accent` | `#f8961e` | Buttons, prompt `$`, cursor, dial progress, link underlines |
| `--sky` | | gradient | Page background, `#06268c` to `#2079e8` |
| `--rail` | | `14.5rem` | Width of the command column |

Orange on azure is about 3:1, so orange is used for fills, marks and underlines, with navy text on orange fills. Orange text sits on navy only.

## Layout

- `.panel`: a flat, square-cornered sheet, `min(100% - 2rem, 64rem)` wide, centred, with a soft shadow. Slightly translucent so clouds show through.
- `.hero`: split 50/50 navy and azure from `lg`, with the dial centred on the seam, intro text on the left and the buttons on the right behind a dotted rule. Stacked below `lg`.
- `.section`: `.cmd` (dark rail, sticky on desktop) beside `.body`. Below `md` the command is a strip above its output.
- Panels are separated by sky, not by lines.

## Motion

All of it stops under `prefers-reduced-motion: reduce`.

| What | How |
| --- | --- |
| Clouds drift | CSS `drift` animation on each `.cloud`, different durations |
| Clouds parallax | `main.js` sets `--sp` (scroll progress) and `--px` / `--py` (pointer) on `<html>`; each cloud multiplies them by its depth `--d` |
| Front clouds | A second `.sky--front` layer above the panels at the screen edges, `lg` and up only |
| Dial | Tick ring rotates slowly; `#dial-progress` fills one segment per unlocked step |
| Paper plane | Turns to face the pointer, sways when idle, loops when clicked and on every unlock |
| Sections | `.reveal` fades up once when it enters the viewport |
| Unlock | New content rises in (`.just-unlocked`) and the page scrolls to it |
| Cards | Hover lifts 4px with a light border and soft shadow |
| Links | `.link`, nav links and the preview button grow to 110% on hover and focus |
| Preview window | Pops in; its steps appear one at a time |

To add a cloud, add an `<img class="cloud cloud--N">` and one `.cloud--N` line setting position (`--x`, `--y`), width (`--w`), depth (`--d`) and drift time (`--t`).

## Unlock game

- A step is any element with `data-unlock`; its value is the command or flag that reveals it. Steps unlock in page order.
- Sections: `data-unlock` goes on `.body`. A locked section collapses to its command; the next one gets a cursor and a `run` button.
- Project cards: `data-unlock="flag{...}"` on the `<article>`. A card's flag is shown at the bottom of the card before it.
- Terminal commands: `help`, `hint`, `whoami`, `reset`, `skip` (also `sudo unlock --all`).
- Completion: `#term-ghost` sits behind the input and shows the first matching command in muted text; Tab or Right Arrow accepts it. The next step is offered first. Flags are offered only once the card showing them is unlocked. Tab with nothing to complete moves focus as usual.
- The terminal bar has no progress counter or skip button: the dial shows progress, `hint` prints it, and `skip` is a command.
- Progress is kept in `localStorage` (`vj:unlocked`, `vj:done`).

Rules:

- Nothing is permanently hidden: "show everything" is in the hero, `skip` works in the terminal, and without JavaScript the page is fully visible.
- The game is decoration, not access control: answers are in the page source.
- Visitor input is compared as a string and echoed with `textContent` only.

## Project preview

- Clicking an unlocked project card, or its `Preview` button, opens `#preview`, a native `<dialog>` styled as a small window. Escape, the close button or a click on the backdrop closes it.
- The window plays the card's `.demo` list, one step every 650ms. Each step is `<li><b>action</b> result</li>`. `Replay` restarts it.
- Steps describe how the project works using only what the resume states. The footer says it is a walkthrough, not a screenshot.
- To show a real screenshot or recording frame, add `data-shot="assets/img/NAME.webp"` to the `<article>`; it appears above the steps.
- A card without a `.demo` list does not open a preview.

## Page edges

`html` has a solid sky colour and `overscroll-behavior-y: none`, so pulling past the top or bottom neither bounces nor exposes a white strip. Side effect: pull-to-refresh is disabled on mobile browsers.

## Security rules

- External links carry `target="_blank" rel="noopener noreferrer"`.
- No `innerHTML`, no `eval`, no inline `<script>`, `<style>`, `style=""` or `onclick=""`. The CSP allows scripts and styles from files only. Setting `element.style` from script is allowed and is how the parallax works.
- A new font, script or image host must be added to the CSP meta tag.
- GitHub Actions in `.github/workflows/deploy.yml` are pinned to commit SHAs.
- Known gaps: `frame-ancestors` cannot be set on GitHub Pages; the contact email is in plain text.

## Do

- Use the tokens and component classes; add a component class when markup repeats.
- Keep panels flat and square. Depth comes from the clouds and shadows.
- Check 390px wide after layout changes.

## Don't

- Add a second accent colour or use the script face beyond the name.
- Put text on or under a front cloud; keep that layer at the screen edges.
- Add motion that ignores `prefers-reduced-motion`.
- Lock content without a skip path.
